Trait architecture

how a portrait is composed

Four orthogonal axes

Identity · fixed per player

Set once when the player is generated, never changes. This is what makes Sharma Sharma.

  • skin_tone — 4 tones in production
  • facial_hair — clean / stubble / mustache / beard
  • country — drives kit + cap colour palette

Role · changes by inning

What the player is doing right now. Drives equipment + view angle.

  • equipment — cap (fielding) · helmet (batting) · grill-up (between balls) · sun hat (slip)
  • view — front (profile) · 3/4 (key moment) · side (scorebar) · back (fielding)

State · changes ball-by-ball

Driven by the live sim — never authored. Maps form/confidence/recent events to one of the 9 expressions or 4 actions.

  • form — hot → confident/happy · cold → disappointed
  • moment — milestone → celebrating · key ball → focused · wicket → angry

Decisions + next moves

  • This is the new C1. Throw out the CSS-drawn cap mocks from the earlier files — we're working from a real illustrated style now, and it's stronger than anything CSS could fake.
  • Side view + cap (the original ask) is the most legible at scorebar size — see the integration row. It carries the silhouette of a Test cap with the peak jutting forward.
  • Expression-as-state is the unlock here. Same player feels alive across the match because the portrait is reacting to the sim. Pairs perfectly with the form/confidence system already in the in-match file.
  • Production assets needed: we'll need this same sheet rendered with the country palette swapped in (Aus green, Eng navy, etc.) and with 4 skin tones × 4 facial hair = 16 base identities × 5 equipment × 4 views × 9 expressions. ~2,880 sprites; doable with a generative pipeline or hand-painted variants atop a base.
  • What to design next: say the word and I'll do (a) the team kit / country palette swatches on this same character, (b) more action poses (bowling delivery, diving catch, appeal), or (c) start applying these to the in-match screen for real.
